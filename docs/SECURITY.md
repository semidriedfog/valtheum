# 보안·백업·복원

현재 구현 기준의 운영 안내다. 파일 형식과 독립 복원 재현 방법은 [VTA1 / VTV2 / VTI1 명세](VTA_FORMAT.md)에 있다.

## 무엇을 암호화하는가

**비밀번호 설정과 암호화는 선택사항이다.** 일반 영상·이미지·이미지 압축 파일·PDF의 열람과 목록·태그·별점·시리즈 관리는 비밀번호 없이 사용할 수 있다. 이 경우 DB와 미디어는 평문으로 남는다. 미디어 암호화나 암호화 메모 저장을 선택할 때에는 먼저 DB를 암호화하고 잠금을 해제해야 한다. PDF 자체의 비밀번호는 라이브러리 비밀번호와 별개다.

| 대상 | 저장 위치 | 보호 범위 |
| --- | --- | --- |
| 평문 DB | `.media_index.db` | DB 암호화 전의 목록·태그·시리즈·별점·이력·썸네일·북마크 |
| SQLCipher DB | `.media_index.secure.db` | 위 DB 정보를 폴더 비밀번호로 암호화 |
| 미디어 키 | `.valtheum/vault.key` | 비밀번호로 보호한 해당 라이브러리의 미디어 마스터 키 |
| 이미지 압축 파일 | `.valtheum/archives/<임의 ID>.vta` | ZIP·tar.zst의 내용과 복원 파일명 |
| 개별 이미지 | `.valtheum/images/<임의 ID>.vti` | 원본 사진 바이트와 복원 파일명 |
| 독립 메모 | `.valtheum/notes/<임의 ID>.vtn` | 메모 제목·본문 |
| 영상 | `.valtheum/videos/<임의 ID>.vtv` | MP4·WebM·MKV·AVI·MOV·M4V의 내용과 복원 파일명 |

DB 암호화와 미디어 암호화는 별도 작업이다. 미디어 암호화에는 먼저 DB 암호화와 잠금 해제가 필요하다. PDF·RAR·7z·일반 `.zst` 파일은 미디어 암호화 대상이 아니다. 암호화는 기존 영상 코덱 지원을 늘리지 않는다.

DB 변환과 미디어 변환은 새 사본을 생성·검증한 뒤 사용한다. **평문 원본은 자동 삭제하지 않는다.** 정상 동작과 백업을 확인한 뒤 DB 보안의 평문 DB 삭제 또는 미디어 암호화의 평문 원본 삭제 기능을 사용한다. 원본 미디어 정리는 암호화 사본 전체와 원본 해시가 일치할 때만 삭제한다. 일반 삭제는 복구 불가능한 보안 삭제가 아니다.

## 비밀번호와 키

- 폴더마다 비밀번호가 다를 수 있다. 새 비밀번호는 10자 이상, UTF-8 기준 최대 1,024바이트다. 앱은 비밀번호를 설정 파일이나 URL에 저장하지 않는다.
- `vault.key`는 DB 키 자체가 아니다. SQLCipher DB는 비밀번호로 독립적으로 암호화되며, 같은 비밀번호로 미디어 마스터 키를 별도로 보호한다. 각 미디어는 새로운 파일 키와 난수를 사용한다.
- `vault.key`는 첫 미디어 암호화 작업을 준비할 때 생성된다. DB 암호화만 사용했다면 없을 수 있다. 필요한 키가 없거나 DB에 기록된 키와 다르면 새 키로 대체하지 않는다.
- **DB 보안 → 폴더 비밀번호 변경**은 DB와 기존 `vault.key`의 비밀번호를 함께 바꾼다. 마스터 키와 `.vta`·`.vtv`·`.vti`·`.vtn` 바이트는 유지하므로 미디어를 다시 암호화하지 않는다. 외부 도구로 DB 비밀번호만 바꾸면 키 파일과 맞지 않을 수 있다.
- 비밀번호 변경 후 DB·키 백업을 새로 만든다. 이전 백업은 이전 비밀번호로 열린다. **이전 키·비밀번호로도 같은 미디어를 복원할 수 있으므로 비밀번호 변경은 유출된 미디어 키의 교체가 아니다.**
- DB 비밀번호를 잊으면 암호화 DB를 열 수 없다. 미디어 복원에는 올바른 `vault.key`와 그 키의 비밀번호가 모두 필요하다. 복원 도구를 다시 빌드할 수 있어도 라이브러리 고유 키를 재생성할 수는 없다.

비밀번호 변경은 검증된 DB·키 사본과 `.valtheum-password-change` 전환 기록으로 중단 복구를 처리한다. 완료 기록 전에 중단되면 다음 폴더 열기에서 이전 DB·키로 복구하고, 완료 기록 후에는 새 상태를 유지한다. 이 폴더가 남아 있으면 임의 삭제하지 않는다.

## DB·키와 미디어를 함께 백업하기

앱의 **백업**은 현재 라이브러리의 `.vtbackup` ZIP 묶음이다. 기본 이름은 `valtheum_폴더명_backup_YYYYMMDD_HHMMSS.vtbackup`이다.

묶음에는 다음이 포함된다.

- 현재 DB의 일관된 스냅샷: `.media_index.secure.db` 또는 `.media_index.db`
- 생성된 미디어 키: `.valtheum/vault.key`
- 구성 설명: `backup.json`, `RESTORE.txt`

**미디어 파일은 포함되지 않는다.** `.valtheum/archives`, `.valtheum/videos`, `.valtheum/images`, `.valtheum/notes` 및 필요한 평문 미디어를 별도 저장장치에도 복사한다. DB와 암호화 미디어의 상대 경로·임의 파일명을 유지해야 한다. 필요한 키가 없거나 불일치하면 백업을 중단한다.

ZIP 자체에는 별도 암호를 걸지 않는다. 암호화 DB와 키는 내부에서도 암호화된 상태지만, DB 암호화 전의 백업 DB는 평문이다. 백업 파일명은 폴더명을 드러낼 수 있으므로 필요하면 저장 창에서 바꾼다.

압축 내부 이미지 삭제나 복원 파일명 변경은 새 `.vta`를 만들고 DB 연결을 바꾼다. 완료 후 **DB·키와 암호화 미디어 백업을 함께 갱신한다.** 오래된 DB 백업이 최신 암호화 파일을 가리킨다고 가정하면 안 된다. 편집에는 새 사본만큼 여유 공간이 필요하며 완료 후 되돌리기 기능은 없다. 압축 내부 이미지를 삭제하기 전에는 암호화 관리에서 남은 평문 원본을 검증·정리해야 한다. 원본이 남아 있거나 존재 여부를 확인할 수 없으면 편집을 시작하지 않는다. 기존 백업에는 삭제한 이미지나 옛 이름이 남을 수 있다. 이전 버전에서 이미 편집하여 원본 검증이 실패하는 경우에는 평문 원본을 직접 확인하고 라이브러리 밖으로 옮겨 보관한 뒤 진행한다. 내용이 다른 원본을 자동으로 삭제하지 않는다.

## 앱에서 라이브러리 복원하기

1. **DB 백업 복원 → 백업 파일 선택**에서 `.vtbackup` 또는 같은 형식의 ZIP을 선택한다.
2. 암호화된 백업이면 **백업 당시 비밀번호**를 입력한다.
3. **저장 위치 선택 후 복원**을 누른다. 선택한 상위 폴더에 `valtheum-restored-…` 새 라이브러리를 만들며 현재 라이브러리와 백업 원본을 덮어쓰지 않는다.
4. 별도 보관한 암호화·평문 미디어를 원래 상대 경로로 복사하고 동기화한다. 누락된 미디어의 DB 기록은 자동 삭제하지 않는다.

수동 복원은 앱을 종료하고 새 폴더에 ZIP을 풀어 DB와 `.valtheum/vault.key`의 위치를 유지한 뒤 미디어를 복사한다. 다른 시점의 `-wal`·`-shm` 또는 다른 라이브러리의 키와 섞지 않는다. 단일 `.db` 백업은 앱의 ZIP 선택 복원 대상이 아니며, 수동 복원 시 올바른 DB 이름과 필요한 미디어 키를 별도로 갖춰야 한다.

## 앱·DB 없이 미디어 원본 복원하기

필수 재료는 **`.vta`·`.vtv`·`.vti`·`.vtn` + 해당 `vault.key` + 키 비밀번호**다. 복원 후 결과물과 복원 중 임시 출력은 평문이다. 모든 구간 인증·길이·SHA-256 검증을 통과한 후에만 최종 출력 이름으로 저장한다. 기존 출력 파일은 덮어쓰지 않는다.

| 도구 | 키 입력 | 출력 선택 | 실행 조건 |
| --- | --- | --- | --- |
| `valtheum-restore.exe` | `vault.key` 또는 키가 포함된 `.vtbackup`/ZIP | 폴더와 여러 암호화 파일 | Windows WebView2 필요 |
| `valtheum-restore-cli.exe` | **추출한 `vault.key` 파일** | 암호화 파일 하나와 명시적 출력 파일 | WebView2 불필요, 비밀번호 숨김 입력 |
| [`tools/restore_vta.py`](../tools/restore_vta.py) | **추출한 `vault.key` 파일** | 암호화 파일 하나와 명시적 출력 파일 | Python·고정 의존성, 출력 파일 시스템의 하드 링크 지원 |

GUI에서는 **키 / 백업 선택 → 저장 폴더 선택 → 암호화 파일 선택 → 비밀번호 입력 → 복원 시작** 순서로 진행한다. 원래 하위 폴더를 재생성하지 않고 파일명만 사용한다. 안전하지 않은 이름은 `recovered-N.<형식>`으로 바꾼다. 파일별 충돌·실패를 표시하고 다음 파일로 진행한다.

CLI 예시이며 출력 폴더는 먼저 만든다.

```powershell
.\valtheum-restore-cli.exe "E:\backup\.valtheum\vault.key" "E:\backup\.valtheum\archives\파일ID.vta" "D:\recovered\원본.zip"
```

영상도 `.vtv` 입력과 원래 영상 확장자의 출력 경로를 지정하면 된다. GUI·CLI는 독립 실행 파일이며 DB나 온라인 서버가 필요 없다. Python 의존성 설치와 공개 테스트 벡터로 복원을 확인하는 방법은 [독립 복원 재현](VTA_FORMAT.md#independent-restoration-and-reproducibility)에 있다.

## 저장 결과를 확인할 수 없을 때

- **시리즈 관리**에서 창을 닫아도 시작한 저장·해제 작업은 계속된다. 다시 열면 같은 작업 상태를 표시한다. 응답을 받지 못하면 실제 시리즈 목록을 확인하며, 확인에 실패하면 **저장 결과 확인**으로 다시 조회한다. 확인 전에는 후속 저장·해제를 막고, 기한이 지난 대기 요청은 서버에서 거절한다.
- **페이지·재생 위치 저장** 후 목록을 읽지 못하면 **저장 목록 다시 불러오기**를 사용한다. 응답 유실만으로 저장 실패를 단정하거나 같은 저장·삭제 요청을 자동 반복하지 않는다. 압축 내부 이미지를 삭제해 페이지 번호가 바뀌어도 남은 북마크의 저장 결과를 확인할 수 있다.
- 압축 이미지의 화면 준비가 10초 안에 끝나지 않으면 페이지 저장 대기를 종료한다. 이미지가 정상 표시된 뒤 다시 저장한다. PDF의 **페이지 저장**(북마크)과 **진도 저장**(마지막 열람 페이지)은 별개이며, 진도 저장 실패 시 **진도 저장 재시도**를 사용한다.

## 빠른 검사·NAS·보호 한계

- **빠른 검사**는 등록된 파일의 존재·크기, DB와 키의 일치, 암호화 파일의 메타데이터·경계 블록을 확인한다. 본문 전체 해시·DB 전체 무결성·압축 내부 이미지 디코딩은 검사하지 않으며, 중간 부분 손상이 통과할 수 있다. 결과는 손상 자동 복구나 백업을 대신하지 않는다.
- NAS 접근 실패는 검사 불가로 표시하고, 파일을 찾지 못했을 때도 이동·연결 상태를 확인한다. 검사·재연결에는 15초 응답 제한과 취소가 있다. 이미 운영체제에서 진행 중인 I/O를 즉시 중단할 수는 없으며, 종료될 때까지 수정 작업이 차단될 수 있다. **라이브러리 닫기**로 화면을 분리할 수 있다. 폴더 동기화 중에도 닫기·잠금은 화면을 즉시 숨기며, 이전 동기화는 취소를 확인하면 DB 반영을 중단한다. 운영체제의 NAS 요청이 끝나기 전에는 같은 라이브러리의 재열기·잠금 해제가 지연될 수 있다. DB 암호화·비밀번호 변경·백업 복원 중에도 라이브러리 닫기는 화면과 현재 세션을 분리한다. 이미 시작된 저장 작업은 안전하게 마무리될 수 있으며, 완료 응답이 이전 라이브러리를 다시 열지는 않는다. 작업이 끝날 때까지 같은 폴더는 다시 열 수 없을 수 있다. 실제 폴더를 여는 중에도 진입창을 닫아 요청을 취소할 수 있다. DB·키 읽기가 늦게 끝나더라도 취소한 라이브러리를 자동으로 표시하지 않는다. 닫기·잠금 응답을 확인하지 못한 경우에는 숨겨진 진입창에서 다시 시도하며 실제 목록을 자동으로 표시하지 않는다.
- `.valtheum.lock`의 운영체제 파일 잠금으로 같은 라이브러리의 동시 사용을 막는다. 파일이 남아 있는 것 자체는 사용 중이라는 뜻이 아니며 수동 삭제하지 않는다. 모든 PC에서 잠금을 지원하는 최신 앱을 사용해야 한다. NAS의 파일 잠금 지원이 필요하고, 현재 WAL 기반 DB의 네트워크 파일 시스템 한계가 없어지는 것은 아니다.
- 시작 화면은 별도 사진 갤러리다. **사진 라이브러리** 라벨을 2.5초 안에 5번 누르면 실제 폴더 선택 창을 연다. 실제 폴더 목록은 실행 중 메모리에만 유지하고 다시 실행할 때 폴더를 지정한다. 공개 갤러리 폴더·액자 시간·언어는 설정 파일에 저장된다. 폴더 미지정 시 내장 기본 사진은 없다.
- 시작 화면과 DB 암호화는 탐색기의 파일 존재·개수·대략적인 크기·시간, OS 기록, 평문 원본·이전 백업을 숨기지 않는다. 잠금 해제 중 화면·메모리를 읽는 프로그램, OS 페이지 파일·덤프의 사본까지 보호하지 않는다. 자동 잠금·Windows 잠금 연동·비밀번호 분실 복구는 제공하지 않는다.
- SQLCipher와 AES-GCM을 사용하지만 valtheum의 컨테이너·앱 전체에 대한 독립 보안 감사를 받은 것은 아니다. 파일 손상을 검출할 수 있어도 정상 백업 없이 손상된 데이터를 자동 복구하지 못한다. 과거의 정상 암호화 파일 전체로 되돌리는 동작도 포맷만으로 차단하지 않는다.

## 독립 메모

**＋ 새 메모**에서 사진 없이 메모를 작성한다. 메모 하나가 목록 항목 하나이며 제목 검색·태그·별점·휴지통을 지원한다. 아레나와 시리즈 대상에는 포함하지 않는다. 제목은 선택 사항이며 최대 UTF-8 512바이트, 본문은 256 KiB다. 공백·줄바꿈·탭·유니코드 원문을 보존한다. 큰 입력란에서 편집하고, 열람 시 글자 크기를 조절하거나 공백을 표시할 수 있다.

저장에는 DB 암호화와 잠금 해제가 필요하며 기존 라이브러리 비밀번호·vault.key를 사용한다. 본문은 DB에 저장하지 않고 독립 암호화 파일인 .valtheum/notes/*.vtn에 저장한다. 제목은 검색용으로 암호화 DB에도 저장한다. 원문 텍스트 파일이나 사진을 준비할 필요가 없다. 빈 제목은 목록에서 Untitled note로 표시한다.

수정은 새 암호화 사본의 제목과 본문이 원문과 일치하는지 검사한 뒤 DB 연결을 교체한다. 실패·취소·수정 충돌 시 기존 메모를 보존한다. 메모 삭제는 기존 미디어 휴지통을 사용하며 영구 삭제 전에는 복원할 수 있다. 기존 백업에 남은 메모는 삭제되지 않는다.

**DB 백업만으로 본문을 복원할 수 없다.** DB·키 백업과 .valtheum/notes를 함께 보관하고 변경 후 함께 갱신한다. 앱 메모 창의 내보내기, 독립 GUI·CLI·Python 복원 도구로 .vtn을 평문 JSON 배열({id,title,body})로 복원할 수 있다. 복원에는 올바른 vault.key와 비밀번호가 필요하다.

열람 화면은 캔버스로 본문을 표시하고 원문이나 화면 이미지를 자동 저장하지 않는다. 편집할 때는 텍스트 입력란을 사용한다. 잠금·폴더 전환 시 화면과 입력 내용을 지운다. 캔버스는 화면 캡처·OCR·메모리 접근을 방지하지 않는다.
