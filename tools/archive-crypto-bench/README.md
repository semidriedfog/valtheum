# 이미지 압축 파일 암호화 성능 비교

2026-09-27 Windows PC에서 측정한 독립 벤치마크다. 합성 이미지와 일회성 키만 사용하며 사용자 미디어·DB·설정·키 파일이나 앱 코드를 변경하지 않는다. 이 도구의 AES 어댑터는 제품 암호화 형식이 아니므로 실제 데이터를 보호하는 용도로 사용하지 않는다.

## 방법과 결과

Rust release 빌드에서 `age` 0.12.1, `aes-gcm` 0.11.1, `zip` 2.4.2, `zstd` 0.13.3을 비교했다. 정확한 의존성은 `Cargo.lock`에 고정되어 있다. 측정 CPU는 `AMD64 Family 25 Model 97 Stepping 2, AuthenticAMD`이며 AES·PCLMUL 기능이 감지되었다.

고정 난수 시드로 만든 1000×1400 RGB 노이즈 이미지 96장을 JPEG 품질 85로 저장했다. Stored ZIP은 101,941,486바이트, tar.zst는 102,009,442바이트(zstd 레벨 3)다. OS 캐시를 예열했으며 파일 열기·인증 복호화·압축 해제·페이지 바이트 읽기를 측정했다. JPEG 디코딩, 화면 표시, 비밀번호 KDF, 앱의 동시 작업은 제외했다.

아래 값은 **중앙값(ms)**이다. 신규 열기·tar.zst는 조건별 9회, ZIP 리더 재사용은 24페이지 × 5회로 비교했다.

| 작업 | 평문 | age 64KiB | AES-GCM 64KiB | AES-GCM 1MiB |
|---|---:|---:|---:|---:|
| ZIP 신규 열기·첫 페이지 | 1.82 | 11.73 | 5.83 | 53.32 |
| ZIP 신규 열기·48페이지 | 1.80 | 9.96 | 5.73 | 54.03 |
| ZIP 신규 열기·96페이지 | 1.63 | 9.81 | 5.48 | 52.89 |
| ZIP 첫 페이지·별도 리더로 2회 | 3.22 | 19.62 | 10.86 | 107.55 |
| ZIP 리더 재사용·순차 페이지 | 0.67 | 1.48 | 0.90 | 0.95 |
| ZIP 리더 재사용·임의 페이지 | 0.68 | 1.49 | 0.99 | 1.36 |
| tar.zst 신규 열기·첫 페이지 | 0.81 | 1.67 | 1.43 | 2.15 |
| tar.zst 신규 열기·48페이지 | 10.36 | 46.33 | 31.25 | 29.70 |
| tar.zst 신규 열기·96페이지 | 19.22 | 90.40 | 60.38 | 51.58 |

표본 수·P95와 개별 조건은 [측정 원자료](results.json)에 보관한다. 모든 측정 페이지와 각 방식의 전체 복원 결과를 원본과 바이트 단위로 비교했다. 이 결과는 ZIP 열람의 64KiB 블록과 리더 재사용을 뒷받침한다. tar.zst 뒤쪽 페이지는 순차 압축 해제의 영향을 크게 받으므로 블록 크기만으로 앱의 체감 성능을 판단할 수 없다.

age는 이미 메모리에 있는 X25519 키를 사용한다. AES 어댑터에는 제품 수준의 키 래핑·헤더/EOF 검증·메타데이터 처리가 없으므로 보안 기능이 동등한 완제품 비교가 아니다. 첫 페이지를 두 번 여는 항목도 순차 모의 작업이며 실제 아레나 UI나 서로 다른 두 파일의 병렬 열람 측정이 아니다. 캐시에 없는 NAS·HDD나 실제 이미지의 성능을 보장하지 않는다.

## 재현과 산출물

프로젝트 루트에서 실행한다. Python과 Pillow가 필요하다.

```powershell
python tools/archive-crypto-bench/generate_fixture.py
cargo run --locked --release --manifest-path tools/archive-crypto-bench/Cargo.toml
```

`target/archive-crypto-bench-data/`의 같은 이름을 가진 합성 데이터와 결과를 덮어쓴다. 데이터 약 1GiB와 별도 Rust 빌드 캐시 공간이 필요하다. 키는 저장하지 않으므로 생성된 암호화 파일은 재사용할 보관본이 아니다. 도구의 `target/` 캐시는 삭제해도 재빌드할 수 있지만 소스·`Cargo.lock`·[기록된 결과](results.json)는 보존한다.
